Post a message silently into another session. This does NOT trigger the LLM there. The message appears in that session and waits — the human or agent in that session must decide what to do next.

Use this tool when you are done with a task and need to report back. The caller's session will show your message with no automatic follow-up.

WHEN TO USE reply vs delegate:

Use reply (this tool) when:
- You were delegated a task and need to report the result back
- You are reporting a result, summary, or status back to the originating session
- You do NOT want to automatically trigger the caller's LLM

Use delegate (not this tool) when:
- You want to actively trigger the LLM in the target session
- You need the target agent to respond and continue working
- You are initiating new work in another session, not closing out a task

HOW REPLY ROUTING WORKS:

The system resolves the reply target automatically from your session context:
1. If replyToSessionID is set on your session — reply goes there (set by delegate tool)
2. Otherwise — reply goes to your parentSessionID (whoever delegated to you)
3. If neither exists — error (orphaned session)

You do not need to specify a session. Just call reply with your message.

AUTOMATIC ROUTING IN DELEGATION CHAINS:
When agents forward delegations, reply routing is preserved automatically:
- Pandora delegates to Project Owner → Project Owner's replyToSessionID = Pandora
- Project Owner delegates to BA → BA's replyToSessionID = Pandora (inherited)
- BA calls reply → message goes to Pandora

This ensures replies reach the original requester even through multiple delegation hops.

Parameters:
- message: the text to post
