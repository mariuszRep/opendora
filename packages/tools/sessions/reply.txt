Post a message silently into another session. This does NOT trigger the LLM there. The message appears in that session and waits — the human or agent in that session must decide what to do next.

Use this tool when you are done with a task and need to report back, but the caller should decide whether to continue. The caller's session will show your message with no automatic follow-up.

WHEN TO USE reply vs delegate:

Use reply (this tool) when:
- You were given reply_to in your session context — this is the expected tool
- You are reporting a result, summary, or status back to the originating session
- You want the caller to see your output and decide what happens next
- You do NOT want to automatically trigger the caller's LLM

Use delegate (not this tool) when:
- You want to actively trigger the LLM in the target session
- You need the target agent to respond and continue working
- You are initiating new work in another session, not closing out a task

HOW REPLY THREADING WORKS:

When reply_to_message_id is set on your session (visible in your <session> context), reply will automatically:
- Target the correct session
- Thread the message under the correct parent message

You only need to provide session_id or parent_message_id explicitly when targeting a session other than the one that spawned you.

Parameters:
- session_id: target session to post into — omit to auto-resolve from session context
- message: the text to post
- parent_message_id: message ID to thread against — omit to auto-resolve from session context
